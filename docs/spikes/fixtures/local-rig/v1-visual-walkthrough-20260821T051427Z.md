**X6（映射两栏 · 1024 与 1440 各看一次）**：两个视口下映射表列头都是

- **目标字段是常驻控件**（不是点开才出现的编辑态），默认预填的就是源名（`ID` / `C_NAME` / `LOAD_DATE`）；
- 主键复选框在场且可点，`ID` 那行已勾；
- **控件 26px、行高 43px，控件没撑破行**（两个视口都是）；
- 映射表 `scrollWidth - clientWidth = 0`——**1024 下也没有横滚**；
- `prefers-color-scheme` 条件规则 **0 条**：第一版没有暗色主题（此处复核）。
- 改目标字段（`ID → C_NAME`）后主键**仍然勾着**（ADR-0039 增补 1 的渲染面成立）。

**与判据字面的两处出入，本轮如实记下、不代所有者改判**：
1. 判据写的是「目标字段是常驻**输入框**」，实测是常驻 **`<select>` 下拉**；
2. 判据写的是「主键勾选在目标字段**右侧**」，实测主键是第 5 列，中间隔着「目标类型」与「约束」。

两处都不是本轮改的——`47a2fed`（*Prepare x2doris P1 frontend handoff*）把映射面从取列表里
拆成独立的 `.field-mapping-section` 并把输入框换成下拉时一并发生，那一票没跑 X 系列。
判据的**意图**（常驻、不是编辑态；主键与目标字段在同一行看得见）两条都仍然成立。

**X7（长度单位标注）**：取列表头逐字 `精度 / 长度（字符）`；
脚下静态说明「长度栏的单位是字符。MySQL 使用 utf8mb4 时， 1 个汉字通常按 3 字节计算。」，
样式实测 `color rgba(0,0,0,.45)` / `background rgba(0,0,0,0)` / `border-width 0px`——
**纯文字、不着色、没长成告警**。

**台架改动（X5–X7 这一段）**：`v1-probe.py` 的 X6 观察由 `.builder-columns`
改指 `.field-mapping-section`，并在观察前**先聚焦再失焦**目标表输入框以触发目标列读取。
旧写法在新 DOM 上取到的是「勾哪几个源列」的取列表，`target_value` 全是 `None`——
那是选择器过时，不是界面回退。这一条写进探针注释里了。

  X12 / X13 / X14 / X15 / X16 / X17 / X18。
