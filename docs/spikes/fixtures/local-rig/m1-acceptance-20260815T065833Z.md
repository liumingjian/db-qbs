## Review conclusions (2026-08-15, coverage-gap follow-up run)

This run adds the two fault scenarios the first real-rig run left uncovered:
`sink-kill-rerun` and `commit-disconnect-discarded`. The three standing review gates were
re-measured and none of them moved:

1. **Push/cursor > 50% on narrow-100k (57.3%), kill-direct (65.0%), sink-kill (68.2%),
   sink-kill-direct (52.4%) and wide (50.1%).** Same finding as the first run: cursor
   lifetimes are 0.7–24 s, far below the minutes-to-hours regime ADR-0007's ORA-01555 risk
   model is about. Serial fetch+push stands.
2. **Commit vs the ADR-0010 30-minute read timeout:** wide 8.6 s (COUNT 153 ms), narrow
   0.61 s, sink-kill-rerun 0.48 s. Headroom unchanged; the timeout needs no adjustment.
3. **Batch bytes vs the ADR-0011 16 MiB budget:** wide max 16,776,616 bytes, under the
   16,777,216-byte budget, byte cutter still firing ahead of the 5000-row cutter
   (21 batches of 4137–4795 rows). No PAYLOAD_TOO_LARGE.

New evidence from the two added scenarios:

- **`sink-kill-rerun`** — the sink was `kill -KILL`ed after the source had pushed 14 of 20
  batches. The source exited 1, its terminal event is `FAILED` at stage `STREAMING`, and it
  emitted **no** `commit_diagnosed` (the commit was never attempted, so there is nothing to
  diagnose). The target table hash still equalled the pre-run sentinel hash, i.e. a sink
  lost mid-stream cannot half-replace the target. After restarting the sink, the rerun took
  a fresh `run_id`, purged 100001 rows and reproduced the direct-run hash exactly.
- **`commit-disconnect-discarded`** — the commit-drop proxy ran in its `discarded` mode
  (`M1_COMMIT_DROP_MODE=discarded`), inflating `total_rows` by one before forwarding so the
  sink's staged-versus-source verification fails, then dropping the connection as usual.
  The source could only recover the terminal from the tombstone: `commit_diagnosed` carried
  `terminal=DISCARDED` with the operator message "目标端报告暂存表已丢弃，目标表未被触碰，
  可直接重跑", the run failed at stage `COMMITTING` with exit 1, the target still held its
  sentinel row (untouched), and the sink had already dropped the staging table (0 staging
  tables left). Together with the pre-existing `commit-disconnect` scenario, both arms of
  ADR-0010's post-disconnect tombstone diagnosis are now covered on the real rig.

Scenario count is 9; `scripts/test-m1-acceptance.sh` gates the new assertions statically.
