## 造态源：这一轮**两遍都跑**——活台架一遍、桩一遍

ADR-0040 §6.3 增补（所有者 2026-08-19 裁定 Q5）判的是「X 系列优先对活台架取观察，桩是回落手段」。

| 遍 | 编排 | 端口 | 主张什么 |

| **桩** | `./walkthrough/run-x-walkthrough.sh` | 18098（`walkthrough/v1-mock.py`） | **X9 里活台架造不出的那部分**：一屏五态（含结局不明、任务已删除）、禁用态的原因文本、预填三规则的「丢弃」那一条、结局不明行重跑时并跑提示**不出现** |

**为什么 X9 仍需要桩**：判据要一屏同时有 FAILED / 结局不明 / 进行中 / SUCCEEDED / 任务已删除五种行。
`unknown_reason` 只在进程消失或服务重启后由 source 补写，「任务已删除但历史还在」要先删任务——
两者都不是 C1–C6 编排得出的态，硬造等于往真库里塞行（那正是 `x-rig-seed.sh` 拒绝做的事）。
**但重跑这个动作本身在活台架上是真的**：下面 X9-a 那条是对着真 sink、真 Oracle 点出来的。

### X9-b（桩那一遍）：一屏五态、禁用态原因、预填三规则、并跑提示的两面

五行五态，操作列逐行实测：

| 行 | 结局栏 | 操作列 | 重跑按钮 |
|---|---|---|---|
| `rec-failed-fa` | DISCARDED 目标表未被触碰 | 有按钮 | `disabled: false` |
| `rec-live-fa` | 进行中 STREAMING | **`—`** | 无 |
| `rec-unknown` | 结局不明 进程消失，无终态日志 | 有按钮 | `disabled: false` |
| `rec-succeeded` | SWAPPED 目标表已切换 | **`—`** | 无 |
| `rec-task-gone` | DISCARDED 目标表未被触碰 | 有按钮 | **`disabled: true`** |

**禁用态不凭空消失、且说得出原因**：`rec-task-gone` 那个按钮的 `aria-label` 与**外层 `.row-actions` 的 `title`**
双双是「重跑（不可用）：任务已删除。重跑按任务当前的规格现算 SQL，规格没了就无从跑起。」
——挂在外层是因为浏览器不给 `disabled` 控件派发指针事件，只挂按钮自己的 `title` 等于没写。

**预填三规则一次现形**：`rec-failed-fa` 行上的参数是 `legacy_region=SH · load_date=2026-08-18`，
任务「财务凭证」当前规格的「运行时填」是 `load_date` 与 `region`。点重跑后对话框里：
- `load_date = 2026-08-18`——**行里有的取行值**；
- `region = ""`——**行里没有的留空**；
- `legacy_region` **不在对话框里**——**行里多出的丢弃**；
- 两个字段 `editable: true`，把 `region` 手填成 `HZ` 后取值变成 `["2026-08-18", "HZ"]`——**改得动**。

**并跑提示的两面**（本轮要害）：
- 从 `rec-failed-fa` 重跑、填满参数后，既有提示照常出现：「该任务以同一组运行参数可能已有一个 run 进行中。
  rec-live-fa · 已跑 30 小时 48 分钟 / 这条提示可能滞后、不是门禁；真正的并发判断由后端在发起时完成。」
- 从 **`rec-unknown`（结局不明）**重跑，预填出 `2026-08-17`，`stale_run_hint` 实测 **`null`——提示条不出现**。
  这正是判据要的那一条：结局不明的 `outcome` 也是 `null`，提示条必须只认**真在跑**的 run，
  不能指着你刚点的那条已死记录。

确认后 `accepted: true`，历史从 5 条变 6 条，表首新增 `rec-new-6`，原五条原样保留。

## 关于队列上的三台 mac

本轮派发过程中 `rexec` 队列上先后出现过三台 mac：`lmjMac-mini-Pro.local`、`C20260623159704`（**没装 docker**）、
`lmjdeMacBook-Pro.local`。派发落到哪台不受调用方控制，三台的环境各不相同（Instant Client、
`x86_64-apple-darwin` 这个 rust target、playwright venv 各有各的缺）。
**因此本批次把四份台架 + 两遍走查合成一次派发**，让它们必定落在同一台上串行跑完，
并让编排脚本自备缺失的环境。批次内所有读数因此同源，可比。
