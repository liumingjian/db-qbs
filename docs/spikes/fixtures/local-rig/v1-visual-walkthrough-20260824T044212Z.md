## 二、新增的 X19

**列结构**：`名称 · 地址 · 状态 · 身份 · 版本 · 最近可见 · 被引用 · 操作`。

**三档状态同屏，颜色分开**（实测 `backgroundColor`）：

| 状态 | 底色 | 那一行还显示什么 |
|---|---|---|
| `在线` | `rgb(82,196,26)`（绿） | 身份 `6f1a9c2d`、版本 `0.1.0`、最近可见 `2026/08/24 10:00:00`、被引用 `2 条数据源` |
| `不在线` | `rgba(0,0,0,0.45)`（灰） | 红字原因 `连不上 agent：Connection refused (os error 111)` |
| `身份不符` | `rgb(245,34,45)`（红） | 红字原因 `这个地址上应答的是另一台 agent（注册时钉的是 c33d8f1a…，现在应答的是 99aa77bb…）` |

**「身份不符」确实比「不在线」更红**：前者是纯红，后者是中性灰——
ADR-0044 §6 那条「换了一台顶替比没起来更该当成事故」在颜色上兑现了。
两条原因**摆在行里，不是只挂 `title`**（截图 `x19-agent-list.png` 第 2、3 行）。

**注册一个打不通的地址**（`http://127.0.0.1:59999`）：对话框里出现
`连不上这个地址上的目标端 agent（http://127.0.0.1:59999）：连不上 agent：Connection refused (os error 111)`，
**列表仍是 3 行，一行都没多**——探不通就不落库这条兑现了（截图 `x19-register-unreachable.png`）。
对话框里 `register_dialog_has_test_button = false`：**没有「测试连接」按钮**，提交本身就是连接。

**把地址改成通的那个**（`http://127.0.0.1:8080`）再提交：列表变成 4 行，新那行
`状态 = 在线`、`身份 = d44e9a2b`、`版本 = 0.1.0`、`最近可见 = 2026/08/24 10:05:00`、
`被引用 = 未被引用`（截图 `x19-registered.png`）。名字仍是上一步填的「走查 · 打不通的」——
**只改了地址、名字不动**，这正是表单该有的行为。

**点一行「探测」**（挑的是不在线那台）：点下去当场采样——
`clicked_row_aria_label = 正在探测`、`clicked_row_disabled = true`，
**另外两行 `[false, false]`**（只锁自己那一行）；落定后 `aria_label` 回到 `探测`，
那一行仍是 `不在线 连不上 agent：Connection refused (os error 111)`，
`dialogs_on_screen = 0`——**探测失败不弹任何对话框**，结果就落在那一行上。

**删一台被引用的**（目标端 A，2 条数据源绑着）：被拒，红底一句
`这台 agent 仍被 2 条数据源引用；请先改这些数据源绑定的 agent`，
下面 `<li>` 列表**点名**：`数仓 MySQL`、`备用 MySQL`（截图 `x19-delete-refused.png`）。

**数据源对话框里的 agent 下拉**（挑一条 MySQL 数据源开编辑）：

```
required: true
options: ["请选择", "目标端 A", "目标端 B（灾备）（不可用）", "目标端 C（迁移中）（不可用）", "走查 · 打不通的"]
submit_disabled_before_switch: false     ← 编辑态、连接字段一字未动，免测连
submit_disabled_after_switch:  true      ← 换一台 agent 之后，保存重新变灰
```

最后那两行是本条的重点：**agent 进了连接指纹**，换一台就等于换了一条到目标库的路，
上一次的测连结果当场作废（ADR-0044 §6）。截图 `x19-datasource-agent-select.png`。

## 四、走查捞出来的三件事（都已就地修掉并重跑）

0. **X19 第一趟根本没量「探测」那一步**——判据里写着、探针里没有。
   那等于把一条判据当成「看着对」放过去了。已补进 `observe_agents`（上面那段采样），
   重跑后才有了上面那五个值。
1. **X19 第一趟量到的 `datasource_agent_dropdown` 是 `null`**——探针点的是列表第一行，
   而第一行是 Oracle 数据源，那条根本没有 agent 字段。**是探针挑错了行，不是字段丢了**。
   已改成按「类型 = MySQL」挑行，重跑后量到了上面那四个值。
   这件事留在这里是因为它正是「记录实际观察」的价值：一个 `null` 如果被当成「通过」写掉，
   本票最要紧的那条判定（换 agent 要重测）就永远没人验过。
2. **「最近可见」那一格原样打印 RFC 3339 串**，在窄列里从 `2026-08-` 中间折成两行。
   已改成与列表屏同一个 `formatTimestamp`（实测 `2026/08/24 10:00:00`，本地时区）——
   同一个时刻在两屏上不该长得不一样。改完重跑了 typecheck / 单测 / 整份 X。
