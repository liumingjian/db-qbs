# M2 渲染面人工走查清单

**规格来源**：[ADR-0028 §6](../../../adr/0028-m2-acceptance-criteria-and-rig-extension.md)
（决策票 [#59](https://github.com/liumingjian/db-qbs/issues/59)）。
屏与态的定形见 [#58](https://github.com/liumingjian/db-qbs/issues/58) 与
[`docs/prototypes/0058-m2-full-flow-prototype.html`](../../../prototypes/0058-m2-full-flow-prototype.html)。
视觉规则的唯一来源是 [`docs/design-system/`](../../../design-system/)。

## 这份清单为什么存在

ADR-0028 §1 把 M2 的自动断言面画在 `source` 的 `/api/*` 上，**不上浏览器自动化**——
DOM 断言会把设计系统的类名与结构变成事实上的契约，让每次视觉调整都变成验收返工。

代价就是这份清单：**API 里根本不存在的东西，只能靠人看。** 它如实记账，不假装没有。

**不给退出码。** 自动验收（`run-m2-acceptance.sh`）的 PASS/FAIL 与本清单互不替代：
前者判「规格错没错」，后者判「渲染错没错」。

## 触发条件（两条，固定）

1. **M2 验收时必跑一次。**
2. **任何改动 `docs/design-system/README.md` 或 `docs/design-system/tokens.css` 的变更，合并前必跑一次。**

跑完**贴实际观察，不是贴「通过」**——照 ADR-0014 §8 第 3 条的先例。

## 走查项

制造情形的手段与自动验收同源（ADR-0028 §3.1 的 A1–A14），走查时可直接复用那套编排造出各态。

### 一、三条形状轴不得互换（ADR-0025 §3）

| # | 打开哪一屏 · 制造什么情形 | 该看见什么 |
|---|---|---|
| V1 | 运行详情 · 进行中 | 阶段串是**三个圆点** `PREPARING ─▶ STREAMING ─▶ COMMITTING` + 尾部文字「→ 终态待定」。**不是五个**；终态不得画成圆点 |
| V2 | 运行详情 · 成功 | 终态是**块**、`SWAPPED` **实心** |
| V3 | 运行详情 · 校验失败 | 终态是**块**、`DISCARDED` **描边** |
| V4 | 运行详情 · 映射预检失败 | 错误码是**标签**；4xx **虚边**、5xx **实边**；码名右边永远跟中文人话结论 |
| V5 | 灰度打印 / 关掉颜色 | V2–V4 的信息**一条不丢**——形状与边型独立于色彩承载信息。**须贴实测数字**（2026-08-16，[#89](https://github.com/liumingjian/db-qbs/issues/89)）：整页 `filter: grayscale(1)` 截图后取 `SWAPPED` 与 `DISCARDED` 块内中位亮度，**差 ≥ 25/255（≈10%）**；「目视可分」不算通过——那句话在 3.1% 时也为真，两轮走查就是这么放过去的。设计系统 §8 |

### 二、轴二只在墓碑真存在时出现（#58 定形 1，设计系统 §3）

| # | 屏 · 情形 | 该看见什么 |
|---|---|---|
| V6 | 运行详情 · 形状预检失败 | **不出终态块**。「目标表未被触碰」在人话结论条里，不是块 |
| V7 | 运行详情 · 映射预检失败 | 同上，不出终态块 |
| V8 | 运行详情 · 进程消失 / 服务重启 | 「结局不明」族**不出终态块、也不出错误码标签** |
| V9 | 运行历史列表 | 「结局」列里**块与中性灰字并存、视觉不齐**（`未发起` / `未建暂存表` / `结局不明`）。**齐了就是假的** |

### 三、两段预检分开是结构不是文案（#58 第 2 问）

| # | 屏 · 情形 | 该看见什么 |
|---|---|---|
| V10 | 运行详情 · 形状预检失败 | 上下两张卡；第二张是**灰色「未执行」占位卡**，明写「没跑到这一段，`sink` 不知道存在这个运行」 |
| V11 | 运行详情 · 映射预检失败 | 第一张卡形状预检**六条逐条列出，通过的也列**（「一次报全部」要看得见）；第二张按 `列名 \| 源端 \| 目标端 \| 违反` 逐列摆 + 末尾总计 |
| V12 | 运行详情 · 形状预检失败 | 这一屏**没有错误码标签**——形状预检是 `source` 本地成文，不属 ADR-0010 的 12 码闭集 |

### 四、业务值的呈现（ADR-0025，定价归 ADR-0024）

| # | 屏 · 情形 | 该看见什么 |
|---|---|---|
| V13 | 运行详情 · 哨兵逃逸 | `column` / `value` 在**独立告警框**里、**默认打码**，需要显式动作才展开 |

### 五、两个 id 与并发提示（#58 第 4/5 问）

| # | 屏 · 情形 | 该看见什么 |
|---|---|---|
| V14 | 运行历史列表 | `run_record_id` 是**第一列、主列、可点**；`run_id` 紧随其后、等宽 `--dim` 灰一号 |
| V15 | 运行详情 · 形状预检失败 | `run_id` 栏位写「**未发起 —— 目标端不知道这次运行**」，**不是空白、不是横杠**；两个栏位谁也不替代谁 |
| V16 | 发起对话框 · 有进行中 run | info 人话条给 `run_record_id` 与已跑时长，并明说提示允许滞后、**只提示不拦你**；**发起按钮不禁用** |
| V17 | 运行详情 · 进行中 | **取消按钮常亮**；点下去当场如实拒绝（禁用状态本身会说谎） |

### 六、构建器与建表 SQL（ADR-0023 / ADR-0027）

| # | 屏 · 情形 | 该看见什么 |
|---|---|---|
| V18 | 建任务 · 手改 SQL | 确认模态明写「整段替换」+「不记得你上次在向导里选了什么」；SQL 框右上角**常驻角标「当前 SQL 已被手改」** |
| V19 | 建任务 · `target_table` 未填 | 表名处是 **SQL 占位符** `<目标表名>`（`--warn` 系虚边 + 底色），**SQL 照给不拦着人先看**；占位符**不进三轴** |
| V20 | 建任务 · 取列成功 | 结果卡下明写「刷新即丢，不进任务定义、不进存储」；建表 SQL 旁 `ERROR 1118` **静态提示**明写「这是静态提示不是判定，执行动作在产品之外」 |
| V21 | 建任务 · 目标端两字段 | **没有目标表下拉、没有目标列列表**，且屏上明写「是不画，不是没画完」 |
| V22 | 运行详情 · 映射预检失败 | 只放「回到取列拿建表 SQL」入口，**不在此重给建表 SQL**（双出口会误导人撞 `ERROR 1050`） |
| V23 | 全局 | 零处「重试」运行的措辞，一律「**重新发起**」 |

|---|---|---|

## 记录格式

每次走查在本仓库开一份 `m2-visual-walkthrough-<UTC>.md`（与 `m2-acceptance-<UTC>.md` 并列），
逐条写实际观察。**「V7 通过」不算记录，「V7：映射预检失败屏无终态块，结论条写『目标表未被触碰』」才算。**
