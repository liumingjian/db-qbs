## 这份清单为什么另立，以及它**不替代**整份 V1–V25

第一版**要跑整份 `m2-visual-walkthrough.md`（V1–V25）**——
`docs/design-system/README.md` 的两处事实性订正照 `CLAUDE.md` 字面触发了它，
[ADR-0039 §9](../../../adr/0039-v1-ui-increments.md) 已裁定认下、不找豁免。
这一点与 M3 那次相反（#102 判的是零设计系统改动，故不触发），**不要照抄 M3 的结论**。

本清单管的是另一件事：**新增的信息位真的渲染出来了没有**（第一版六屏，
2026-08-21 起并入 P1 的列表工作流，见 [ADR-0042](../../../adr/0042-p1-list-workflows.md)；
同日 [ADR-0043](../../../adr/0043-p2-job-center.md) 把运行历史屏并进作业中心，屏数收到五屏）。
两份并存，互不替代——V1–V25 判「设计系统还是不是原来那套」，X 系列判「这一版新加的东西长对了没有」。

**不并进 V 系列**：并进去之后「跑过整份 V1–V25」这句话的含义会随第一版漂移，
而它恰恰是本版要跑的那份门禁对象。理由与 [ADR-0040 §2](../../../adr/0040-v1-acceptance-criteria-and-rig-extension.md) 的四入口分立同源。

**不给退出码。** 自动验收（`run-v1-acceptance.sh` 的 C 系列）判「配得进去、搬得对、报告说对没有」，
本清单判「渲染出来没有」。

| **X20** | 构建器 · 在「源表」模式下先选一张表、读列、勾几列，再点「自定义 SQL」这个 tab；确认切换后写一段 `SELECT`、读结果列、勾掉其中一列 | 取数方式的两个 tab 长在**源表 / 自定义 SQL 那张卡的头上**（不在数据源卡的页脚），与「读取表 / 读取列」同排。**有东西可丢时**切换弹一次确认，点掉就什么都不变；**空白状态下切换不弹**——没有可丢的东西还要人确认是纯骚扰。确认后源表 / 结果列 / 字段映射 / 主键 / 过滤条件**一并清空**。SQL 模式下：卡片标题、tab、字段标签**三处都叫「自定义 SQL」**（不叫「源 SQL」「源端查询方式」）；**「过滤条件」卡不消失**，留一句说明过滤要写进 SQL；**「构建 SQL」预览照常渲染**，且看得见外层投影把用户的 SQL 包成了子查询（`FROM ( … ) q`）——用户写的 SQL **不原样执行**，这里是唯一能核对最终语句的地方；勾掉一列后**该列从预览的投影里消失**（勾选真的生效，不是空点击）。DBLINK 一栏在 SQL 模式下**不出现**（路径已经写在 SQL 里了）。`>=`、`!=` 在 textarea 与预览里都**按字面显示**，不被连字画成 `≥` `≠`。**增补（ADR-0046 §1）**：输入框**有语法高亮**——关键字、单引号字面量、数字、**双引号标识符**各自着色，且**双引号标识符与单引号字面量不同色**（Oracle 上两者天差地别）；高亮层与输入层**逐像素同框**，光标不飘、占位符仍看得见。工具条右侧有**「格式化」**按钮：已经是格式化后的样子时**禁用**；点一下按子句换行重排，且**只动空白——非空白记号逐字不变**（一个字符都不许改，包括不许把关键字改成大写）；**格式化后已读的结果列与已勾的主键都还在**（语义没变，不该被清掉） |

## 记录格式

每次走查在本目录开一份 `v1-visual-walkthrough-<UTC>.md`（与 `v1-acceptance-<UTC>.md` 并列），逐条写实际观察。

**「X3 通过」不算记录，「X3：填错口令点测试连接，1.2s 后出红字『ORA-01017 用户名/口令无效』，
