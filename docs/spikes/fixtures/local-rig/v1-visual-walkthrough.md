## 这份清单为什么另立，以及它**不替代**整份 V1–V25

第一版**要跑整份 `m2-visual-walkthrough.md`（V1–V25）**——
`docs/design-system/README.md` 的两处事实性订正照 `CLAUDE.md` 字面触发了它，
[ADR-0039 §9](../../../adr/0039-v1-ui-increments.md) 已裁定认下、不找豁免。
这一点与 M3 那次相反（#102 判的是零设计系统改动，故不触发），**不要照抄 M3 的结论**。

本清单管的是另一件事：**新增的信息位真的渲染出来了没有**（第一版六屏，
2026-08-21 起并入 P1 的列表工作流，见 [ADR-0042](../../../adr/0042-p1-list-workflows.md)；
同日 [ADR-0043](../../../adr/0043-p2-job-center.md) 把运行历史屏并进作业中心，屏数收到五屏）。
两份并存，互不替代——V1–V25 判「设计系统还是不是原来那套」，X 系列判「这一版新加的东西长对了没有」。

**不并进 V 系列**：并进去之后「跑过整份 V1–V25」这句话的含义会随第一版漂移，
而它恰恰是本版要跑的那份门禁对象。理由与 [ADR-0040 §2](../../../adr/0040-v1-acceptance-criteria-and-rig-extension.md) 的四入口分立同源。

**不给退出码。** 自动验收（`run-v1-acceptance.sh` 的 C 系列）判「配得进去、搬得对、报告说对没有」，
本清单判「渲染出来没有」。

| **X16** | 作业中心 · 一屏里同时有跑完的、跑一半的、没跑过的、以及一条开跑前计数失败的任务 | 「迁移进度」列只有**一个整数百分比** + 一条细进度条：**不带小数、不附行数**（ADR-0043 §7）。**向下取整**——造一条 99.98% 的失败运行，这一格必须显示 `99%`，`100%` 只在真跑完时出现。三种空态互不混淆：**尚未运行**是 `—`（不是 `0%`）；**开跑前计数失败**是 `—` 且 `title` 自陈「未取到总行数」，但那次运行**照常跑完**、状态列该是什么是什么；**进行中**有真百分比（分母是开跑前 `COUNT(*)` 拿到的），不是不确定进度条（ADR-0026 §3 已被推翻） |
| **X17** | 作业中心 · 一屏里五种运行状态同时在场 | 「运行状态」列五个词——成功 / 失败 / 进行中 / 结局不明 / 尚未运行——**都是同一种实心方角标签**（`--badge-radius: 0`，白字，`尚未运行` 是描边中性态）。**齐是对的**：这一列是**一维索引**，不是轴二，V9 那条「齐了就是假的」已随 ADR-0043 §4 反转退役。**这一列上不出错误码标签、不出终态块**——三轴在抽屉里（X18） |
| **X18** | 作业中心 · 点一条失败任务行的「运行详情」图标 | 右侧开抽屉（不是新页、不是模态居中框），标题写「运行详情 · 任务名」、旁边是 `run_record_id`。分区齐全：**人话结论条 + 轴二块 + 轴三错误码标签**（形状与 V2 / V3 / V4 / V7 一致，只是搬进抽屉）、行数核对、分段耗时（**含「开跑前计数」单独一栏**，不混进读取耗时）、任务定义（**主键 / 条件**）、运行参数与两个 id（`run_id` 那栏见 V15）、源端 SQL。**原运行历史屏展开行里有的，一样不少**。底部重跑入口见 X9。抽屉里**只有最近一次运行**，且明说这一点（多次历史本版不做，ADR-0043 §2） |

## 记录格式
