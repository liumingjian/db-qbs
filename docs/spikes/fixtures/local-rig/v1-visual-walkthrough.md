## 这份清单为什么另立，以及它**不替代**整份 V1–V25

第一版**要跑整份 `m2-visual-walkthrough.md`（V1–V25）**——
`docs/design-system/README.md` 的两处事实性订正照 `CLAUDE.md` 字面触发了它，
[ADR-0039 §9](../../../adr/0039-v1-ui-increments.md) 已裁定认下、不找豁免。
这一点与 M3 那次相反（#102 判的是零设计系统改动，故不触发），**不要照抄 M3 的结论**。

本清单管的是另一件事：**六屏新增的信息位真的渲染出来了没有**。
两份并存，互不替代——V1–V25 判「设计系统还是不是原来那套」，X 系列判「这一版新加的东西长对了没有」。

**不并进 V 系列**：并进去之后「跑过整份 V1–V25」这句话的含义会随第一版漂移，
而它恰恰是本版要跑的那份门禁对象。理由与 [ADR-0040 §2](../../../adr/0040-v1-acceptance-criteria-and-rig-extension.md) 的四入口分立同源。

**不给退出码。** 自动验收（`run-v1-acceptance.sh` 的 C 系列）判「配得进去、搬得对、报告说对没有」，
本清单判「渲染出来没有」。

## 触发条件（两条，固定）

1. **第一版验收时必跑一次。**
2. **任何改动数据源屏、构建器映射两栏 / 目标端下拉的渲染结构、运行历史的重跑入口 /
   发起对话框预填，或 ADR-0039 §9 那四条 `web/src/app.css` 新增规则的变更，合并前必跑一次。**

跑完**贴实际观察，不是贴「通过」**——照 [ADR-0014](../../../adr/0014-precision-and-boundary-contract.md) §8 第 3 条的先例。

## 走查项

制造情形的手段与自动验收同源（ADR-0040 §4 的 C1–C5），走查时可直接复用那套编排造出各态。

| # | 打开哪一屏 · 制造什么情形 | 该看见什么 |
|---|---|---|
| **X1** | 任意屏 · 看导航 | 数据源是**第三项**，与既有两项同一套导航元素，**没有新造的样式**（ADR-0039 §1） |
| **X2** | 数据源列表 · 录满 5 条（Oracle 与 MySQL 各若干） | **没有搜索框、没有类型筛选**（3~5 条一屏看得完）；**没有「连接状态」列**；**有「被引用」列**（`3 个任务` / `未被引用`）；「连接」一列 **Oracle 显示 `connect_string`、MySQL 显示 `host:port / database`**，各显各的、不拼一个假的统一连接串（ADR-0039 §2） |
| **X3** | 新建数据源对话框 · 填一组**错的**凭据 | 「测试连接」当场给失败；**保存按钮不放行**，存不进去（所有者 2026-08-19 裁定 2）。改成对的凭据、测连通过后，成功提示是 `.inline-result` **一行纯文字**，不是标签、不套 `--ok-bg`（ADR-0039 §3） |
| **X4** | 编辑一条**已被任务引用**的数据源 · 只改名称，然后删它 | 只改名称**免测连**即可保存；删除被**拒绝**，报文**点名列出**引用它的任务，不是一句笼统的「无法删除」（ADR-0039 §4、ADR-0037 §7） |
| **X5** | 构建器 · 目标端 | 目标表是原生 `<input list>` + `<datalist>` 的**可过滤下拉**——键入片段能筛，**也允许直接键入**；口令栏的「已设置 / 未设置」是 `.field-badge.is-neutral` **中性色**，不是成功 / 失败色（ADR-0039 §5、§9 表第 2 条） |
| **X6** | 构建器 · 映射两栏 · 视口 **1024** 与 **1440** 各看一次 | 目标字段是**常驻输入框**（不是点开才出现的编辑态），默认预填源名；**主键勾选在目标字段右侧**；未映射的目标列整行**压暗**（`.data-grid tr.is-unmapped td`）。两个视口下输入框与单元格**等高、不撑破行**，第一版**没有暗色主题**（ADR-0025 正面否掉，此处复核）（ADR-0039 §6） |
| **X7** | 构建器 · 取列卡看长度栏 | 表头写「长度（**字符**）」，脚下贴一句**静态说明**「预检按字节判」——**纯文字、不着色、不长成告警**（同 W3 的态度）。两套 `length` 单位第一版**不修**，只标注（ADR-0039 §7、ADR-0033） |
| **X8** | 任务屏 | 新增一列「源 → 目标」，显示的是**数据源名字，不是 id**；这一列不引入新组件、不着色（ADR-0039 §8） |
| **X9** | 运行历史 · 一屏里同时有 FAILED / 结局不明 / 进行中 / SUCCEEDED / 任务已删除五种行 · 点其中一条失败行的「重跑」 | 「操作」列里：FAILED 与结局不明的行**有**「重跑」；进行中与 SUCCEEDED 的行**没有**（给破折号占位，不是空白）；任务已删除的行有一个**禁用**的重跑并说明原因（原因挂在外层 `.row-actions` 的 `title` 与按钮的 `aria-label` 上——浏览器不给 `disabled` 控件派发指针事件，挂在按钮自己的 `title` 上等于没写），**不凭空消失**。点「重跑」打开的是**既有的发起对话框**（标题仍是「发起运行 · 任务名」、确认键仍是「发起」，只是上下文行多一句「重跑自 <run_record_id>」）；参数按「行里有的取行值 / 行里没有的留空 / 行里多出的丢弃」预填，且**全部可改**；填满后「同一组参数可能已有 run 进行中」的既有提示照常出现——但**重跑一条结局不明的行时它不出现**（结局不明的 `outcome` 也是 `null`，提示条必须只认真在跑的 run，不能指着你刚点的那条已死记录）；确认后是一条**新的**运行历史记录，失败旧记录原样还在（ADR-0041 增补 2、规格 [#149](https://github.com/liumingjian/db-qbs/issues/149) A 段） |

## 记录格式

每次走查在本目录开一份 `v1-visual-walkthrough-<UTC>.md`（与 `v1-acceptance-<UTC>.md` 并列），逐条写实际观察。

**「X3 通过」不算记录，「X3：填错口令点测试连接，1.2s 后出红字『ORA-01017 用户名/口令无效』，
保存按钮保持禁用；改对口令再测，出一行灰底纯文字『连接成功』，保存按钮放行」才算。**
