## 一、三条形状轴不得互换

### V1 · 运行详情 · 进行中
- 该看见：三个圆点 `PREPARING ─▶ STREAMING ─▶ COMMITTING` + 尾部「→ 终态待定」；不是五个；终态不得画成圆点
- **实际观察**：从 `#tasks` 发起「A5 正常 10 万行」（child 停在 `hang-streaming`），运行详情阶段串渲染为
  `PREPARING 准备中 → STREAMING 传输中 → COMMITTING 提交中`，**恰好三个**，每个前面一个
  `.phase-dot`（计算样式 `width/height: 8px`、`border-radius: 50%`，是真圆点）；当前阶段的点
  背景 `--info` 并带 3px 光晕。串尾是纯文字 `→ 终态待定`（`.phase-after`，**无圆点**）。
  组件层 `RunPhase` 类型只有三个字面量，结构上无法变成五个。**符合。**

### V2 · 运行详情 · 成功
- 该看见：终态是块、`SWAPPED` 实心
- **实际观察**：`real` 模式跑完 A5（100,000 行 / 20 批 / 4481.7 KiB），终态渲染为
  `SWAPPED　目标表已切换`，计算样式 `border: 1px solid rgb(196,236,214)`、
  `background: rgb(240,250,244)`、`border-radius: 3px`、`padding: 3px 9px` —— 是**块**，
  且底色边色正是 `--ok-bg` / `--ok-bd`，与设计系统 §61「`SWAPPED` 实心（`--ok-bg`/`--ok-bd`）」逐值吻合。**符合。**

### V3 · 运行详情 · 校验失败
- 该看见：终态是块、`DISCARDED` 描边
- **实际观察**：起 `commit-drop-proxy.py`（verify 模式）跑 A8，终态渲染为
  `DISCARDED　目标表未被触碰`，计算样式 `border: 1px solid rgb(220,222,226)`、
  `background: rgb(248,248,249)` —— 即 `--line-strong` / `--mute-bg`，与设计系统
  §61「`DISCARDED` 描边中性（`--mute-bg`/`--line-strong`）」逐值吻合。**符合。**
  结论条：「目标端：校验未通过：源端读出 100001 行 / 20 批，sink 只收到 100000 行 / 20 批——有批次未送达。目标表未被触碰，可直接重跑。」

### V4 · 运行详情 · 映射预检失败 —— **有偏差**
- 该看见：错误码是标签；4xx 虚边、5xx 实边；码名右边永远跟中文人话结论
- **实际观察**：
  - 标签形状 ✔：`.error-code` 计算样式 `padding: 2px 8px`、`border-radius: 3px`、等宽字体，是标签不是块。
  - 边型 ✔ 且三例齐全：`PRECHECK_FAILED HTTP 422` → `border-style: dashed`（虚边）；
    `VERIFY_FAILED HTTP 409` → `dashed`；`INTERNAL_PRECHECK_ESCAPE HTTP 500` → `solid`（实边）。
    分档逻辑在 `DesignSystem.tsx`：`httpStatus === undefined || >= 500 → is-internal`，否则 `is-rejected`。
  - **偏差：中文人话结论在码名左边，不是右边。** 实际 DOM 顺序是
    `<span>{conclusion}</span>` 然后才是 `<span class="error-code">`，屏上读作
    「目标端：映射预检未通过：一次发现 1 项问题，未创建暂存表　`PRECHECK_FAILED HTTP 422`」。
    结论**确实永远伴随码名**（这一半达成），只是方位与清单写的相反。

### V5 · 灰度打印 / 关掉颜色 —— **部分不达标，这是本次最有价值的一条**
- 该看见：V2–V4 的信息一条不丢——形状与边型独立于色彩承载信息
- **实际观察**：对运行历史列表（同屏同时有 `SWAPPED` 块、`DISCARDED` 块、两种错误码标签、
  中性灰字、左竖线四种形态）加 `filter: grayscale(1)` 后逐一比对：
  - 块 / 标签 / 中性灰字 / 左竖线**四种形态本身在灰度下完全可分** ✔
  - 错误码 **虚边 vs 实边在灰度下清晰可分** ✔（`422`/`409` 虚线框 vs `500` 实线框）
  - **✘ `SWAPPED` 实心块与 `DISCARDED` 描边块在灰度下无法区分。** 两者都是 1px 实线边 + 浅底色，
    灰度亮度几乎相等：底色 `#F0FAF4` → 灰度 ≈246，`#F8F8F9` → ≈248；边色 `#C4ECD6` → ≈222，
    `#DCDEE2` → ≈222。截图上两个块看起来是同一种浅灰填充框。
  - 信息**没有真的丢**，因为块里写着字面码名 `SWAPPED` / `DISCARDED` 和中文旁白
    「目标表已切换」/「目标表未被触碰」，读者靠文字仍能分辨。
  - **但设计系统 README §148 那句「黑白打印/复印下三轴仍可分（实心块 vs 描边块 vs 虚线标签 vs 实线标签）」
    对「实心块 vs 描边块」这一对不成立**：实现把「描边」做成了「中性底色的填充块」而不是「无底色只有边」，
    这与 §61 的 token 指派（`DISCARDED` 用 `--mute-bg`）是一致的——**缺口在设计系统内部，
    §61 与 §148 互相打架，不是实现跑偏。** 要修得改其中一条，属于设计决策，未擅自改动。

  + `PRECHECK_FAILED HTTP 422` 标签，**无 `.terminal-block`** ✔。
  措辞是「未创建暂存表」而非清单里的「目标表未被触碰」，语义等价，记实况。**符合。**

### V8 · 运行详情 · 进程消失 / 服务重启
- 该看见：「结局不明」族不出终态块、也不出错误码标签

  `outcome　FAILED` + **`结局不明`** + `进程消失，无终态日志` + 一句明写
  **「没有错误码，也没有目标端终态块。」** DOM 里既无 `.terminal-block` 也无 `.error-code` ✔。
  历史列表里 `PROCESS_DISAPPEARED` / `SERVICE_RESTARTED` 四条同样：错误码列是 `—`（`.empty-value`），
  结局列是 `.unknown-summary`（只有 `border-left`，无底色无圆角，不是块）。**符合，且屏上还把这条规则写成了人话。**

### V9 · 运行历史列表 —— 齐了才是假的
- 该看见：块与中性灰字并存、视觉不齐
- **实际观察**：同屏四种形态确实并存且高度/形状明显不齐：
  - `SWAPPED` / `DISCARDED`：带底色带边框的块，`padding: 3px 9px`、`border-radius: 3px`
  - `未发起` / `未建暂存表`：`.neutral-outcome`，纯 `--mute` 灰字，`border: none`、`padding: 0`
  - `结局不明`：`.unknown-summary`，无底色无圆角，只有 3px `border-left`；
    并且 `PROCESS_DISAPPEARED` 用 `solid` 左边线、`SERVICE_RESTARTED` 用 `double` 左边线——
    **同族内部再靠边型细分，且不依赖颜色**
  截图上这一列参差得很明显。**符合。**

## 六、构建器与建表 SQL

### V18 · 建任务 · 手改 SQL —— **模态符合，角标缺失**
- 该看见：确认模态明写「整段替换」+「不记得你上次在向导里选了什么」；SQL 框右上角常驻角标「当前 SQL 已被手改」
- **实际观察**：新建任务里手打 `SELECT 1 FROM dual` 后点按钮，弹出确认模态：
  标题**「重走向导会覆盖你手改的 SQL」**，正文**「构建器会用新生成的四字段整段替换当前内容，也不会恢复上一次的勾选状态。」**
  ——「整段替换」✔，「不记得你上次选了什么」以「也不会恢复上一次的勾选状态」表达 ✔，
  按钮是「取消」/「覆盖并重走向导」。
  - **✘ SQL 框右上角没有任何常驻角标。** 全仓库搜不到「已被手改」字样。唯一的「已被手改」信号是
    构建器区那个按钮从「打开构建器」变成了「重走向导」——这是个**要靠记忆才能读出的隐性信号**，
    不是清单要的常驻角标。

### V19 · 建任务 · `target_table` 未填 —— **行为符合，视觉标记缺失**
- 该看见：表名处是 SQL 占位符 `<目标表名>`（`--warn` 系虚边 + 底色）；SQL 照给不拦着人先看；占位符不进三轴
- **实际观察**：留空 `target_table` 点「拿建表 SQL」，DDL 正常返回，正文里是
  `CREATE TABLE <目标表名> (` ✔，**SQL 照给、没拦人** ✔，占位符没有被当成任何标签/块渲染 ✔。
  - **✘ 占位符没有任何视觉标记。** `<pre class="ddl-output">` 内部**一个子元素都没有**
    （`querySelectorAll('*')` 返回空），整段 DDL 是纯文本，`<目标表名>` 与其它 SQL 文本
    在字体、颜色、边框上完全一样。清单要的 `--warn` 虚边 + 底色**没实现**。
  - 旁边那句「随时可取；目标表名为空时，DDL 会保留可见占位符。」用文字兜了底。

### V20 · 建任务 · 取列成功 —— **1118 提示符合，「刷新即丢」那句缺失**
- 该看见：结果卡下明写「刷新即丢，不进任务定义、不进存储」；`ERROR 1118` 静态提示明写「这是静态提示不是判定，执行动作在产品之外」
- **实际观察**：取列成功后出现列表卡（表头 `结果集列名 | describe 类型 | 精度 / 长度`，
  三行 `ROW_ID (8,0)` / `V_TEXT (200)` / `D_BIZ -`）+ `CREATE TABLE` 卡 + 复制按钮。
  - `ERROR 1118` 提示 ✔：独立的 `--warn` 框，标题**「执行时若报 ERROR 1118 Row size too large」**，
    正文**「列宽合计超出 MySQL 单行上限，需缩窄字符列或拆表；这是静态提示，产品不预先判定行长。」**
    「这是静态提示不是判定」✔。「执行动作在产品之外」由 DDL 首行注释
    「请自行执行；产品不会替你建表。」承担 ✔。
    （本次 G1 真把 70 列那版拿去 MySQL 执行，**真报了 `ERROR 1118`**——这条提示是准的。）
  - **✘ 「刷新即丢，不进任务定义、不进存储」这句不存在。** 最接近的是构建器区标题旁的
    「一次性生成四字段，选择状态不会保存」，说的是勾选状态不是取列结果；DDL 区那句
    「随时可取」也不等于「刷新即丢」。**「不进存储」这层意思屏上没写。**

### V21 · 建任务 · 目标端两字段 —— **结构符合，「是不画」那句缺失**
- 该看见：没有目标表下拉、没有目标列列表，且屏上明写「是不画，不是没画完」
- **实际观察**：构建器展开后只有源端三步（`数据库链接（可选）` → `Oracle 表` 下拉 → `读取列` →
  `生成四字段`）；目标端自始至终**只有 `target_table` 和 `target_date_col` 两个纯文本框**，
  **没有目标表下拉、没有目标列列表** ✔。
  - **✘ 屏上没有「是不画，不是没画完」这类明写。** 最接近的一句是构建器标题旁
    「Oracle 字典元数据仅展示，不判定类型是否可搬」——那是在说别的事。
    结果是：**结构上做对了，但没人告诉用户这是故意的。**

### V22 · 运行详情 · 映射预检失败 · 出口 —— **不重给符合，入口缺失**
- 该看见：只放「回到取列拿建表 SQL」入口，不在此重给建表 SQL
- **实际观察**：A7 那屏**没有重给建表 SQL** ✔（不会诱导人去撞 `ERROR 1050`）。
  - **✘ 但也没有「回到取列拿建表 SQL」的入口。** 全屏只有「返回任务」和「重新发起」两个动作，
    人看完「目标表缺少同名列」之后，**没有任何指路**，得自己想到去新建/编辑任务里点「拿建表 SQL」。
    清单说的是「只放这一个入口」，实际是「一个入口也没有」。

### V23 · 全局「重试」措辞
- **实际观察**：全仓库 `web/src/` 搜「重试」只命中一处：`errors.ts` 的兜底文案
  「请求失败，请稍后重试」——说的是**HTTP 请求**，不是运行。
  与运行相关的动作一律是**「重新发起」**（终结后的按钮、`onRelaunch`），
  取消后按钮也立刻变成「重新发起」。V3 的结论条里有一句「可直接重跑」——是「重跑」不是「重试」。
  **零处「重试」运行的措辞，符合。**

## 七、导航与排版

### V24 · 全局导航
- **实际观察**：左侧导航只有两项 `任务` / `运行历史`；其下一个小标题**「非 V1 范围」**，
  底下 `定时调度` 和 `告警` 两条，各自右侧一个 `M3+` 灰标，**不可点、无链接** ✔。
  **构建器不是导航项** ✔——它是「新建任务 / 编辑四个字段」对话框里的一个可展开区域
  （`region "SQL 构建器"`）。**符合。**

### V25 · 字体与主题 —— **字体族/字重/主题符合，`tabular-nums` 有缺口**
- 该看见：中文系统字体栈；数字独立等宽栈 + `tabular-nums`；强调字重 600 不是 700；没有暗色主题
- **实际观察**：
  - 中文 ✔：`body` 计算出 `"PingFang SC", "HarmonyOS Sans SC", "Source Han Sans SC", …`
  - 数字等宽栈 ✔：id / 行数 / 耗时 / 时间戳全部 `ui-monospace, "SF Mono", "JetBrains Mono", …`；
    行数还带千分位（`100,000`）
  - 字重 ✔：`th`、`h1`、`.task-name`、各处 `strong` 计算值都是 **600**；
    全仓库 CSS 搜不到 `font-weight: 700` 或 `bold`
  - 无暗色主题 ✔：`web/src/` 里搜不到 `prefers-color-scheme`，也没有 `data-theme`
  - **✘ `tabular-nums` 没有全面生效。** `tokens.css:52` 把它挂在 `.num, td.n` 上，
    但**应用里根本没用这两个类名**，用的是 `.mono` / `.numeric-column`（`app.css:77,88`），
    这两个类只设了字体族与字号，**没有 `font-variant-numeric`**。实测运行历史表里
    行数/耗时/时间戳列的计算值都是 `font-variant-numeric: normal`。
    只有运行详情的 `.run-metrics dd` / `.identity-grid dd` 显式写了 `tabular-nums`（`app.css:111,212`）。
    **结论：详情屏有，列表屏没有——而恰恰是列表屏最需要数字对齐。**

## 八、附带看到的渲染缺陷（清单没问，但既然看了就记）

1. **运行历史「结局」列列宽不足，终态块被挤成竖排。** 1440×960 视口下，
   `DISCARDED　目标表未被触碰` 的旁白被折成「目标/表未/被触/碰」四行，块被撑到约 80px 高，
   把整行行高拉垮，同屏行高参差得不像设计（截图见走查过程）。`SWAPPED　目标表已切换` 同样折成两行。
   V9 要的「不齐」是**语义上的不齐**，这个是**排版失控**，两回事。
2. **导航高亮与主区内容不一致**：从运行详情屏看，左侧「运行历史」仍处于 `is-active` 高亮，
   而面包屑已经是「数据导入 / 运行详情」。运行详情不属于任何导航项，高亮停在上一个页面。
3. `GET /favicon.ico` 404，控制台每次加载一条错误。无功能影响。

## 九、总评

**渲染走查判定：通过，但带 12 条待办偏差 + 1 条设计系统内部矛盾。**

三条形状轴的**结构性要求全部成立**——三阶段圆点不多不少、终态只在墓碑真存在时才出块、
错误码按 4xx/5xx 分虚实边、两段预检是两张卡而不是两段文案、两个 id 并列不互相替代、
构建器不是导航项、零「重试」措辞、无暗色主题。**ADR-0025 / ADR-0012 / #58 定形的那些
「不许互换」的底线，实现没有一条越界。**

偏差分三类，都不动语义：

- **文案缺句（6 条）**：V6 缺中文结论与「目标表未被触碰」、V10 缺「sink 不知道存在这个运行」、
  V11 说明列是英文、V16 缺 `run_record_id` 与已跑时长、V20 缺「刷新即丢，不进存储」、
  V21 缺「是不画，不是没画完」。这些句子存在的意义都是**替用户解释「为什么屏上是这样」**，
  缺了它们，做对的结构会被当成没做完。
- **视觉标记未落地（3 条）**：V14 `run_id` 没压成 `--dim`、V19 DDL 占位符没有 `--warn` 虚边底色、
  V25 列表屏没开 `tabular-nums`。
- **元素位置 / 缺件（3 条）**：V4 中文结论在码名左边而非右边、V18 缺「当前 SQL 已被手改」常驻角标、
  V22 缺「回到取列拿建表 SQL」入口。

外加**一条设计系统内部矛盾**（V5）：§61 让 `DISCARDED` 用 `--mute-bg` 填充，
§148 又声称「实心块 vs 描边块」在黑白下可分——两者不能同时成立，实测灰度下这一对确实分不开。
**这条得先定，才谈得上改实现。**

一条也没有影响 A1–A14 的 API 语义，因此**不阻塞 M2 自动验收的 14/14**；但按 ADR-0028 §6，
渲染走查与自动验收互不替代，上面这 12 条应作为 M2 的渲染尾账单独记票，不要混进 M3。
