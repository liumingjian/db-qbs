# V1 战略地图

目标读者：负责实现的 agent 与维护者。术语见 `CONTEXT.md`，关键决策见 `docs/adr/`。

## 一句话

**通用的离线数据库导入方案**：用户在源端 Web UI 选表选字段生成 SQL，查 Oracle，把结果安全地
搬进目标端 MySQL，重跑不产生脏数据，搬完能证明两端一致。**两端网络隔离**是前提，
**任意一对 Oracle / MySQL** 都是适用对象——具体客户环境是**第一个部署**，不是设计基准
（定位见 `CONTEXT.md` 抬头与 [ADR-0005 增补](adr/0005-local-rig-as-v1-verification-baseline.md)）。

## 成功标准

V1 交付即可投入第一个部署，判据是下面五条同时成立。
**五条都按能力判，不按某个具体库判**——判据要在任意符合形态的源表上成立：

1. 在一张 **70+ 列、10 万行量级的宽表**上跑通全链路，数据逐字段可对账。
   「70+ 列 / 10 万行」是**规模形态**，不是某一张特定的表：它压的是行宽对批次切分的影响、
   流式内存形状与端到端时长。基准是本地台架上等价构造的宽表（ADR-0005 四类可信度表，
   这些量落在「客户端侧行为，完全可信」）；**每个部署自己那张表的列清单与类型**
   属部署事实，走部署前检查单，命中白名单外类型时由预检拒绝并点名到列（ADR-0009 §8）。
2. 任意时刻杀掉源端进程或断网，重跑后目标表状态与一次跑成完全一致。
3. 金额字段无任何精度损失（ADR-0003）。
4. 任务失败时，错误信息能直接指向原因（哪一列、哪个类型、哪个批次），不需要翻日志猜。
   **2026-08-16 达成**（[#91](https://github.com/liumingjian/db-qbs/issues/91)、
   [ADR-0029](adr/0029-failure-classification.md)）：措辞点名到列与值早已到位，本次补上分类——
   `failure_kind` 16 值闭集进日志、历史与界面，M4 那条要求区分的六类各自可单独判出；
   sink 侧写批次的三个成因也从两个别处的码里拆了出来。**M4 的「错误分类可诊断」因此提前兑现，
   那一格剩下的只有重试与延迟重推。**
5. 重跑同一业务日期，目标表不出现重复行。

## 非目标

MySQL → Oracle 反向、自动建目标表、鉴权、定时调度、多表事务一致性、千万行级优化。

## 里程碑

### M0 — Oracle 驱动 spike（风险闸门）—— ✅ 已通过（2026-08-13）

**结论：继续 Rust，驱动定 `oracle` crate（ODPI-C）。M1 可以启动。**
完整报告与实测数据：[`docs/spikes/0001-oracle-driver.md`](spikes/0001-oracle-driver.md)（闸门决策见 §7）。

原计划是在客户生产表上实测两个候选驱动。实际走成了两处不同：

- **候选 `oracle-rs` 出局**——它要求服务端 ≥ 12.1，客户源端是 11g。M0 因此从「择优」
  塌缩成「ODPI-C 单点验证，没有备胎」。
- **客户环境要不到**（不是暂时排不上，是拿不到）。验证基准改为本地 Docker 台架，
  判据按「模拟层压在哪一侧」重划——见 [ADR-0005](adr/0005-local-rig-as-v1-verification-baseline.md)。

按重划后的判据，四条全部成立：类型保真度 `FAIL 0`、`NUMBER` 38 位字符串原样、
内存峰值与总行数无关、客户端每行 CPU 外推 70 列 × 10 万行 ≈ 1.5 秒、Instant Client 可部署。
附带：dblink **列投影 Oracle 自己会推**、**绑定变量能穿过 dblink**（ADR-0004 方案不改）。

**代价写在明面上**：服务端绝对吞吐、`ZHS16GBK` 往返、真实类型清单等 6 项台架答不了，
已转 [#2 的上线前复验清单](https://github.com/liumingjian/db-qbs/issues/2)——
**那是已知风险，不是通过项**，M4 收尾前必须在真实源端跑一遍。其中「真实吞吐」一项若不符，
触发 ADR-0001 复审、回退 Java——那正是 M0 本想在第 0 天挡住的事。

产出：spike 报告（已提交）+「Oracle 类型 → 规范形式 → MySQL 类型」映射表草案（报告 §7.3）。
映射表另带出 6 条 M1/M3 必须落实的正确性约束（报告 §7.4），其中
`CHAR` 目标类型必须是 `VARCHAR`、`DECIMAL` 标度必须逐位相等两条直接影响两端 checksum 可比。

### M1 — 端到端最小骨架

打通**最窄的一条**完整链路，SQL 先写死，不做 UI。
逐条规格由地图 [M1 端到端最小骨架规格](https://github.com/liumingjian/db-qbs/issues/22) 定稿，
本节只划里程碑边界。

**三条收窄前提**（地图已定，M1 内不再重开）：

1. **类型只支持最小子集**：`NUMBER(p,s)`（有声明精度）/ `VARCHAR2` / `DATE`，
   其余一律预检拒绝、不许跑。类型完备性转 M3。
2. **失败即整 run 失败**：不重试、不暂存、不续传——丢弃暂存表、目标表不动、报错给人。
   失败批次延迟重推在 M4；它重放首次物化的批次载荷，不从 Oracle checkpoint 续读（ADR-0018）。
3. **SQL 写死，不做 UI**。构建器在 M2。

范围：

- `source` / `sink` 两个二进制，HTTP 协议定义（开任务 / 推批次 / commit / 查状态）。
- **单查询流式**读 Oracle → 分批推送 → 落暂存表 → **行数校验** → 原子切换
  （ADR-0002、ADR-0007）。一条 SQL 一个游标边 fetch 边攒批，不做分页 SQL、不要求排序键；
  批次是纯粹的推送切分单位，固定 5000 行，序号只做顺序断言与诊断。
- 规范形式实现，配套边界值测试套件（ADR-0003 指明这是正确性单点）。
  **行 checksum 不在 V1**——校验只比行数（ADR-0006）。
- **映射预检的最小规则**：ADR-0006 把预检从「省事的做法」升格为**硬门禁**，
  不通过不许发起运行。V1 去掉行 checksum 之后，它是「值没有被悄悄改掉」的唯一防线，
  spike §7.4 的六条硬约束一条都不能少。M1 只做最小规则，完整形态在 M3。
- 业务日期作为运行参数贯穿两端（ADR-0004）。

**验收**（基准是本地 Docker 台架，不是客户生产库——ADR-0005；真实源端复验挂在
[#2](https://github.com/liumingjian/db-qbs/issues/2) 的上线前清单里，M4 收尾前跑）：

- 台架 10 万行端到端跑通，目标表数据与源查询逐值一致。
- 跑到一半 kill 源端：暂存表被丢弃、目标表未被触碰；重跑（从头，不续传）结果一致。
- 故意让源端少推一批制造**行数不一致**，确认切换被拒绝、目标表未被触碰。
- 目标表缺列 / `DECIMAL` 标度不足 / 含白名单外类型三种情况，预检在发起运行**之前**拒绝。

### M2 — SQL 构建器

- 读 Oracle 元数据（`ALL_TAB_COLUMNS` 等）列出表与字段供选择。
  **列名前缀约定（`N_`/`C_`/`D_`/`ID_`）只能当辅助提示，类型必须以元数据为准。**
- 选表 → 选字段 → 配 WHERE 条件 → 生成 SQL，列投影写进内层子查询。
- 生成的 SQL 展示给用户，允许手改；改后做静态检查，拒绝相对时间表达式（ADR-0004）。
- 任务定义可保存复用，业务日期不入定义。

**验收**：能通过 UI 重建出用户那条生产查询的参数化版本，字段一个不差。

### M3 — 映射预检与目标表辅助

逐条规格由地图 [M3 搬运语义放宽——类型完备性与映射规则规格](https://github.com/liumingjian/db-qbs/issues/94)
定稿（2026-08-16 收图，9 票），本节只划里程碑边界。

**范围已按实况重画（2026-08-16，见地图 Destination）**：下面三项里，第三项「生成建表 DDL」
已由 M2 的 [#57](https://github.com/liumingjian/db-qbs/issues/57) / [ADR-0027](adr/0027-target-ddl-generation-and-cross-end-metadata.md)
**提前兑现**，第一项是 M1 [ADR-0009](adr/0009-m1-mapping-precheck-rules.md) §8 的现货。
M3 的真身是**类型白名单从三种扩到有依据的 N 种**、**映射恒等与逐位相等两条约束的去留**、
以及 **`DATE` 值域那个明文缺口（ADR-0009 §10）收口**——一句话：
**M2 买的是可操作性，M3 买的是「能搬的东西变多」。**
第二项（列名映射）在地图 [#100](https://github.com/liumingjian/db-qbs/issues/100) 单开一票，
**允许判「不做、用 `AS` 别名兜住」**；下面的验收措辞已由
[#103](https://github.com/liumingjian/db-qbs/issues/103) 重写完毕。

- 任务启动前预检：源查询结果列 vs 目标表结构，列名、类型、精度逐项比对，
  不匹配直接拒绝启动并指出具体哪一列。**尤其是 `DECIMAL(p,s)` 标度不足**（ADR-0003 已知坑）。
- ~~列名映射策略：Oracle 大写带引号 → MySQL 小写，允许用户覆盖。~~
  **已判不做（[#100](https://github.com/liumingjian/db-qbs/issues/100)，2026-08-16，
  落 [ADR-0009 增补](adr/0009-m1-mapping-precheck-rules.md)）**：不引入字段映射表。
  列名对齐仍按 ADR-0009 §3 恒等——比较时统一大写，因此大小写不同的目标表本来就能过预检；
  要改列名用 SQL 里的 `AS` 别名，那不是映射，别名即目标列名，映射仍恒等。
  生成的建表 DDL 列名保持与源端字面一致，不折小写（表名同理，MySQL 表名大小写敏感）。
- 生成 MySQL 建表 DDL 文本给用户拿去执行——**服务本身不建目标表**。

**验收**（2026-08-16 由 [#103](https://github.com/liumingjian/db-qbs/issues/103) /
[ADR-0032](adr/0032-m3-acceptance-criteria-and-rig-extension.md) 重写；
原措辞「目标表少一列 / 标度不足 / 类型不兼容三种情况」**M1 就已经全过了**，作废）：

1. [ADR-0030](adr/0030-m3-type-whitelist.md) §1 **九行形态每行**的边界值端到端搬对——
   字符族与日期族逐字节相等，`DECIMAL` 族按目标标度补零后逐格相等（矩阵写死在 ADR-0032 §4.1）。
2. ADR-0030 §2 **每条**拒绝规则都真的拦得住，且映射预检**一次报全部列**。
3. 裸 `NUMBER` 的全量值域校核**正反两面都验**——超域当场拒且暂存表一张不建，
   不含裸 `NUMBER` 的任务**零扫描**。

**前置**：先跑绿 `run-m1-acceptance.sh` 与 `run-m2-acceptance.sh` 两份；
M3 另起第三个入口 `run-m3-acceptance.sh`，渲染面另立 `m3-visual-walkthrough.md`（W1–W6）。

### M4 — POC 加固

- 任务进度与状态可视化：当前批次、已推行数、耗时、失败原因。
- 失败批次延迟重推：重放 source 本地持久化的原始载荷，不重新查询 Oracle（ADR-0018）。
- 遗留暂存表回收（进程崩溃时 DROP 未执行）。
- ~~错误分类可诊断：区分 Oracle 连接失败 / dblink 不可用 / 类型映射错 / 网络中断 /
  MySQL 写入失败 / 校验不通过——对应成功标准第 4 条。~~
  **2026-08-16 提前做完**（[ADR-0029](adr/0029-failure-classification.md)）：用户要求这一条
  达成之后才继续 M3，故从 M4 前移。分类形态在 M4 不再重开。
- 运行历史留档，可查某次运行搬了多少行、两端行数是否一致。

**验收**：在**一个真实部署**上连续跑一周日常增量，无人工干预。（这一条按定义只能在真实部署上收，台架不替代。）

## 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| ~~Rust Oracle 驱动保真度不足~~ | ~~阻断，需换语言~~ | **M0 已验掉**：ODPI-C `FAIL 0`（spike §2） |
| ~~dblink 不下推投影~~ | ~~拉全表列，性能不可用~~ | **M0 已验掉**：Oracle 自己会推，70 列只有 4 列过网（spike §5.1） |
| **服务端真实吞吐远超「几十秒」** | **ADR-0001 复审，回退 Java** | 台架不可测（ADR-0005），转 #2 复验清单第 4 项；客户端那一半已排除（spike §4.7） |
| **某部署的源表命中 ADR-0003 白名单外的类型** | 映射预检拒绝，该表搬不了 | 刻意选的代价（#11）；白名单的扩张按**类型面覆盖 + 目标端往返实测**推进（M3 图 [#94](https://github.com/liumingjian/db-qbs/issues/94)），不等任何一个部署的分布 |
| **`ZHS16GBK` 中文往返未测** | 乱码或长度截断，M1 返工 | 台架是 `AL32UTF8` 且改不了；已带完整 Basic 包降低概率，转 #2 复验 |
| **两端 checksum 因目标列定义而不可比** | 校验门禁永远不过或误判 | spike §7.4：`DECIMAL` 标度逐位相等、`CHAR`→`VARCHAR`；M1 落地前补台架往返实测 |
| 清除条件与源端 WHERE 范围不等价 | **静默数据重复/丢失，校验抓不到** | 两者强制由同一业务日期推导（ADR-0002 结尾） |
| 规范形式实现有 bug | 全链路正确性崩塌 | 专门的边界值测试套件，视为一等公民 |
| 切换事务锁 10 万行时间过长 | 目标端阻塞 | M1 实测；不预先优化 |
| LLM 迭代被 Rust 编译时间拖慢 | 进度风险 | 同步 IO 降复杂度；编译派发到外部机器 |
