# V1 战略地图

目标读者：负责实现的 agent 与维护者。术语见 `CONTEXT.md`，关键决策见 `docs/adr/`。

## 一句话

在客户环境做 POC：用户在源端 Web UI 选表选字段生成 SQL，查 Oracle，把结果安全地
搬进目标端 MySQL，重跑不产生脏数据，搬完能证明两端一致。

## 成功标准

V1 交付即 POC 就绪，判据是下面五条同时成立：

1. 用生产那张 70+ 列的表跑通全链路，10 万行量级，数据逐字段可对账。
2. 任意时刻杀掉源端进程或断网，重跑后目标表状态与一次跑成完全一致。
3. 金额字段无任何精度损失（ADR-0003）。
4. 任务失败时，错误信息能直接指向原因（哪一列、哪个类型、哪个批次），不需要翻日志猜。
5. 重跑同一业务日期，目标表不出现重复行。

## 非目标

MySQL → Oracle 反向、自动建目标表、鉴权、定时调度、多表事务一致性、千万行级优化。

## 里程碑

### M0 — Oracle 驱动 spike（风险闸门）

**在这之前不写任何业务代码。** 唯一目的是打掉 ADR-0001 里那个未决风险。

用生产那张表（含 dblink）实测两个候选驱动 `oracle` 与 `oracle-rs`：

- 每种实际出现的字段类型能否读出、保真度如何——重点 `NUMBER` 高精度、`DATE`、
  中文 `NVARCHAR2`；生产表里如有 `CLOB`/`TIMESTAMP WITH TIME ZONE` 一并覆盖。
- 能否以字符串形式取到 `NUMBER` 的完整精度（ADR-0003 的前提）。
- 分页/流式 fetch 在 10 万行上的吞吐与内存占用。
- 经 dblink 查询时，列投影是否下推到远端——看执行计划（ADR-0004）。
- 部署成本：`oracle` 需要 Instant Client，确认客户源端机器上装得了。

**通过判据**：至少一个驱动能保真读取全部生产字段类型，且部署可行。
**不通过则触发 ADR-0001 复审**，回退 Java——不要硬扛。

产出：一份 spike 报告 + 一张「Oracle 类型 → 规范形式 → MySQL 类型」映射表草案。

---

### M1 — 端到端最小骨架

打通一条最窄的完整链路，SQL 先写死，不做 UI。

- `source` / `sink` 两个二进制，HTTP 协议定义（开任务 / 推批次 / commit / 查状态）。
- 流式分页读 Oracle → 分批推送 → 落暂存表 → 校验 → 原子切换（ADR-0002）。
- 规范形式与 checksum 实现，配套边界值测试套件（ADR-0003 指明这是正确性单点）。
- 业务日期作为运行参数贯穿两端（ADR-0004）。

**验收**：生产表 10 万行跑通；手动 kill 源端后重跑，目标表结果一致；
故意改一行数据制造 checksum 不匹配，确认切换被拒绝、目标表未被触碰。

---

### M2 — SQL 构建器

- 读 Oracle 元数据（`ALL_TAB_COLUMNS` 等）列出表与字段供选择。
  **列名前缀约定（`N_`/`C_`/`D_`/`ID_`）只能当辅助提示，类型必须以元数据为准。**
- 选表 → 选字段 → 配 WHERE 条件 → 生成 SQL，列投影写进内层子查询。
- 生成的 SQL 展示给用户，允许手改；改后做静态检查，拒绝相对时间表达式（ADR-0004）。
- 任务定义可保存复用，业务日期不入定义。

**验收**：能通过 UI 重建出用户那条生产查询的参数化版本，字段一个不差。

---

### M3 — 映射预检与目标表辅助

- 任务启动前预检：源查询结果列 vs 目标表结构，列名、类型、精度逐项比对，
  不匹配直接拒绝启动并指出具体哪一列。**尤其是 `DECIMAL(p,s)` 标度不足**（ADR-0003 已知坑）。
- 列名映射策略：Oracle 大写带引号 → MySQL 小写，允许用户覆盖。
- 生成 MySQL 建表 DDL 文本给用户拿去执行——**服务本身不建目标表**。

**验收**：目标表少一列 / 标度不足 / 类型不兼容三种情况，预检都能在跑之前拦下并说清楚。

---

### M4 — POC 加固

- 任务进度与状态可视化：当前批次、已推行数、耗时、失败原因。
- 断点续传：按批次序号续推，不从头来。
- 遗留暂存表回收（进程崩溃时 DROP 未执行）。
- 错误分类可诊断：区分 Oracle 连接失败 / dblink 不可用 / 类型映射错 / 网络中断 /
  MySQL 写入失败 / 校验不通过——对应成功标准第 4 条。
- 运行历史留档，可查某次运行搬了多少行、checksum 是多少。

**验收**：在客户环境连续跑一周日常增量，无人工干预。

## 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| Rust Oracle 驱动保真度不足 | 阻断，需换语言 | M0 闸门，不通过就回退 Java（ADR-0001） |
| dblink 不下推投影 | 拉全表列，性能不可用 | M0 看执行计划；必要时改写 SQL 形状 |
| 清除条件与源端 WHERE 范围不等价 | **静默数据重复/丢失，校验抓不到** | 两者强制由同一业务日期推导（ADR-0002 结尾） |
| 规范形式实现有 bug | 全链路正确性崩塌 | 专门的边界值测试套件，视为一等公民 |
| 切换事务锁 10 万行时间过长 | 目标端阻塞 | M1 实测；不预先优化 |
| LLM 迭代被 Rust 编译时间拖慢 | 进度风险 | 同步 IO 降复杂度；编译派发到外部机器 |
