## 背景

[#36](https://github.com/liumingjian/db-qbs/issues/36) 的线框撞出四条冲突，ADR-0017 §7 一条不解、
全部留给 M2。C1（历史）已由 ADR-0020 关闭，C3（校验失败取证）仍属 ADR-0013 的「不留现场」。
**本 ADR 关闭剩下的 C2（进行中的实时观察）与 C4（进度百分比）**。

这两条一直是雾，理由写在地图上：推还是拉、有没有常驻通道，取决于 source 的进程形态与运行历史两票。
两票都已解，问题形状收窄成一句话：

> **ADR-0019 §4 那份内存投影怎么送到浏览器，以及它能不能变成一个百分比。**

投影的性质是本 ADR 每一条决策的判据：它是**明文非权威、尽力而为的日志投影**（ADR-0019 §4 的降级条款）。
下面反复出现的同一句推理是——**任何让投影承担它没承诺过的东西的设计，都要先把那条降级条款废掉**。

## 决策

### 1. 传输选轮询：`GET` 取当前快照，1s 周期，页面不在前台即停

浏览器每 1s 打一次已有的 `/api/*` JSON GET（ADR-0019 §9：UI 与 API 同进程同端口）。
**不新增协议、不新增长连接、不新增失效面。**

被否掉的两条，致命处明写：

- **SSE**：断线之后必须回答「重连要不要补发漏掉的事件」。**补发**就要父进程为每个浏览器维护
  事件游标与队列——那是把一份尽力而为的内存投影**升格成一条有保序与补发承诺的事件流**，
  ADR-0019 §4 的明文降级当场失效；**不补发**则它相对轮询只剩「省几个请求」，撑不起一条新通道。
- **WebSocket**：除上一条外多一个双向通道。取消已经是 REST 动作（ADR-0019 §8 / 本 ADR §5），
  一条双向通道存在着就会长出「顺便把命令也走这里」的第二套表达——正是 ADR-0019 §4
  拒绝「子进程回调父进程本地 HTTP」时拒绝过的同一种病。

**选它的正面理由不是省事，是语义同构**：轮询每次问的都是「现在这一瞬的快照」，
本来就不承诺不漏事件——这与投影的性质逐字一致。

**周期 1s 写死，不给配置项。** 配置项要长期维护、要写进文档、要在排障时反问「你调过没有」，
而它买到的是零：调快无意义（投影更新是内存级的，网络与渲染撑不住，也没人分辨得出 200ms），
调慢等于要人自己挑一个更差的延迟。

**页面不在前台即停轮询**（`visibilitychange`）。这不是优化：挂着的后台标签页会在一个无鉴权端口上
持续打请求，那笔账 ADR-0024 已经认下，没必要再往上加。

**致命处**：延迟等于轮询周期；页面开着就一直发请求。两条都接受。

### 2. 投影逐行更新，但只存聚合标量，不存批次列表

父进程每读到一行 `batch_pushed` 就更新内存投影。**逐行更新与 ADR-0020 §6「不逐批写」不冲突**：
那条挡的是**写盘**，一次内存赋值不是 IO。反过来，做节流会凭空造出「投影落后于日志」的
第二个不一致源——本来只有一个（父子通道本身）。

**「不逐批推」不需要单独定**：轮询只取当前快照，一个 run 打 20 行还是 20000 行 `batch_pushed`，
与请求数无关。这是 §1 选轮询的直接副产品。

投影每 run 只存这几个标量：

| 字段 | 来源 |
|---|---|
| `stage` | `stage_changed.stage`（ADR-0012 五态，未进入时为 `null`——即 ADR-0019 §3 的「已受理」） |
| `seq` | 最新一行 `batch_pushed.seq` |
| `rows_pushed` | `batch_pushed.rows` 累计（等价于最新一行的 `source_rows`） |
| `bytes` | `batch_pushed.bytes` 累计 |
| `ms` | `batch_pushed.ms` 累计 |
| `last_ts` | 最新一行的 `ts` |

**不留批次数组。** 留了它内存就随 run 长度无界增长——ADR-0017 §3 那个「10 万行约 20–37 批」
是一次取样不是上界，没有任何规格说一个 run 只搬 10 万行——而 UI 需要的四个数，一个都不依赖历史批次。

### 3. 不买 `COUNT(*)`：不给百分比，给不确定进度条 + 四个真数

**C4 正面回答：不买。** 理由不是照搬 ADR-0013 §1（那条讲门禁需要同一读一致性视图，
而进度条不当门禁，直接搬会被驳倒），是它的**同构变体**：

> 分母来自另一个 SCN，分子来自 ADR-0007 那个单一快照的游标累加器——**两个数不在同一个读一致性视图里**。

源表在跑时有并发写入，百分比因此可能冲过 100%，也可能永远停在 97%。
**一个会说谎的进度条比没有进度条更糟**，而且它会被当成校验用——与 ADR-0023 §10 判掉
SQL 构建器数据预览的是同一条理由（V1 的防线是映射预检，不是肉眼）。

第二笔账是真金白银：`COUNT(*)` 要按同一谓词再扫一遍，纯粹为一个装饰数字延长 run 的总时长，
而 ADR-0007 明写游标寿命风险随「寿命 × 源表并发写入量」涨——**为装饰付 `ORA-01555` 的风险**。

**替代明写**（全部来自 §2 的投影，零新增字段）：

- **不确定进度条**（indeterminate），不显示任何百分比；
- **阶段串**（五态圆点，ADR-0025 轴一）；
- **键值网格**给四个数：已推行数 / 当前批次序号 / 已用时 / 累计字节。

这两件东西正是 ADR-0025 设计系统 §7 为「实时进度」预留的组件，**不新造组件**。

### 4. 三种「没有投影」的情形各有呈现，共用一个「结局不明」族

| 情形 | 出处 | 呈现 |
|---|---|---|
| 已受理、子进程尚未进入 `PREPARING` | ADR-0019 §3 | 阶段圆点全灰、第一个脉冲，文案「已受理，正在拉起」。**不伪造 `PREPARING`**——§3 明说它不进五态 |
| 子进程消失且无终态日志 | ADR-0019 §3 | 终态 `FAILED`，人话结论固定为「**进程消失，无终态日志**」 |
| 父进程重启，非终态行被启动清扫封口 | ADR-0020 §6 | 终态 `FAILED`，人话结论固定为「**服务重启，结局未知**」 |

后两种**一律不给错误码**：ADR-0010 的闭集（ADR-0022 之后 12 码）是 source↔sink 的协议错误码，
往里塞一个只发生在父进程视角里的原因，等于让协议闭集为非协议事件背书。
ADR-0025 那条「码名右边永远跟中文人话结论」在这里退化成**只有人话**，并提示去看 stdout
（取证面仍是日志本身——ADR-0021 §1）。

**这三者与真失败（有码、可能带 `column` / `value`）在视觉上必须可分**：真失败走错误码标签（轴三），
「结局不明」族只出人话结论条，没有标签。

> **2026-08-15 订正（[#58](https://github.com/liumingjian/db-qbs/issues/58)，画原型时逼出来的两处）。**
>
> 1. **上表第一行原文写「五个阶段圆点全灰」，订正为三个。** ADR-0012 的五态含 `SUCCEEDED` / `FAILED`，
>    而 [ADR-0025](0025-m2-visual-language-and-design-system.md) §3 的硬规则是「三轴形状不得互换」——
>    终态属于轴二的**块**，把它画成圆点当场违规。阶段串固定为
>    `PREPARING ─▶ STREAMING ─▶ COMMITTING`，尾部跟一句文字「→ 终态待定」。
>    **本节其余一字不改**：全灰、第一个脉冲、不伪造 `PREPARING` 全部照旧。
> 2. **「结局不明」族除了不出错误码标签，也不出终态块。** 本节原文只写了「没有标签」，
>    但同一条理由更强地适用于轴二：**墓碑在 `sink` 手里**，父进程没看见结局就不知道有没有墓碑，
>    画一个 `DISCARDED` 是**捏造一条不存在的记录**——比塞一个错误码更糟。
>    「目标表未被触碰」这句话在这一族里**不能说**，因为确实不知道。
>    这条已连同预检未过的两种情形一起进 `docs/design-system/README.md` §3。

### 5. 取消按钮常亮，点下去当场如实拒绝；拒绝走 `/api` 自己的 409

**不预先禁用。** 禁用要依赖投影判断「现在是不是 `COMMITTING`」，而投影可能落后——
**禁用状态本身会说谎**：该禁的没禁（人以为点得动，其实早过封口点），不该禁的禁了
（人以为停不了，其实还在 `STREAMING`）。权威判定在父进程手里，它握着子进程句柄。

```
POST /api/runs/<run_record_id>/cancel
  → 202  已发 SIGTERM（PREPARING / STREAMING）
  → 409  已过封口点，停不了（COMMITTING）
```

**409 的原因串属于 `/api`，不进 ADR-0010 的 12 码闭集。** ADR-0022 新增 `SWAP_TARGET_BUSY`
是因为它真的是 sink 在协议上报的东西；本条只发生在浏览器与父进程之间。

**取消成功也不是新状态**：子进程走已有失败路径（发 abort、清暂存表），终态 `FAILED`——
ADR-0019 §8 原文，本 ADR 一字不改。

这条与 ADR-0022「UI 只提示不拦截」是**同一条口径**：**投影不做门禁**。

### 6. 一个端点，投影优先、历史回落，按 `run_record_id` 寻址

```
GET /api/runs/<run_record_id>
  ├─ 内存投影里有   → 返回投影 + live: true
  └─ 没有           → 返回 SQLite 历史行 + live: false
```

- **寻址必须是 `run_record_id`，不是 `run_id`。** `run_id` 由**子进程**在 SQL 形状预检通过之后
  才生成（ADR-0019 §7 被 ADR-0020 §3 订正的那条），父进程受理发起的那一刻它还不存在，
  UI 手里只可能有 `run_record_id`。
- **run 终结即丢弃投影。** 这让「投影的生命周期」不需要单独的规则：终态那一刻历史行已经封口
  （ADR-0020 §6），装的度量比投影更全。前端不换接口、不判断该问谁，只看 `live` 决定继不继续轮询。

### 7. 只有进行中详情页轮询

历史列表页**进入时拉一次 + 一个手动刷新按钮**。它的内容按定义是已封口的行，自动刷新唯一能变的是
「别人刚发起了一个新 run」——那属于 ADR-0022 已定的并发提示面（只提示不拦截），不是历史列表的职责。
**全站轮询是那种一旦开了就再也收不回来的默认。**

### 8. UI 不做日志尾随

C2 的原始诉求里有一句「M1 只有 stdout 尾随」，本 ADR **正面判它出局**。

UI 要 tail，父进程就得把子进程 stdout 的**原始行**缓存起来供轮询取——而 ADR-0021 §6 刚刚把
「stdout 无界增长且无轮转」作为**明知缺口**记进 `CONTEXT.md`，并明说程序不建文件、不轮转。
把同一条无界流搬进内存再开个窗口，是**把那笔已经认下的账在产品里又付一遍**。

取证面仍然是日志本身（ADR-0021 §1）。进行中视图给的是投影：阶段串 + 四个数 + 失败时的
`column` / `value` 告警框（ADR-0025 §5，默认打码）——这覆盖了人在跑的时候真正会问的两件事：
**它到哪一步了、它是不是卡住了**。

主方向那句的对偶「不做这件事，闭环能不能成」——**能**。

## 后果

- **ADR-0017 §7 的 C2 与 C4 两行关闭**，四条冲突至此关掉三条（C1 归 ADR-0020，C2/C4 归本 ADR）；
  **C3 不变**，仍是 ADR-0013 的「失败即 `DROP`、不留现场」。
- **ADR-0019 一条不订正**：§3 的两个边缘情形第一次有了呈现（§4），§4 的降级条款成了本 ADR
  四条决策的共同判据，§8 的取消第一次有了接口形态（§5），§9 的同端口被 §1 直接用上。
- **ADR-0020 §6 那句「归 C2」兑现**：批次级进度留在内存投影里，且本 ADR §2 给它定了边界
  （只存标量），历史存储没有变成进度存储。
- **ADR-0010 的错误码闭集仍是 12**，本 ADR 不加一个码（§4、§5）。
- **ADR-0025 设计系统零改动**：§3 与 §4 用的全是已预留的组件（阶段串、键值网格、人话结论条、
  业务值告警框）。其 §7「实时进度（仍在雾里）」一行的**雾已散**，改为指向本 ADR。
- **子进程与 sink 零改动**，M1 搬运链路继续只被包装——地图主方向兑现。
- **新增的账两笔，都接受**：进行中视图的延迟等于 1s 轮询周期；页面开着就持续打请求。

## 时效

- §1 的轮询在**引入鉴权**（V1 非目标）或**多任务并行观察成为常态**时重开：前者会让长连接
  第一次有除「省请求」之外的理由，后者会让「每页一个 1s 轮询」的成本第一次真的可见。
- §3 的「不买 `COUNT(*)`」在**源表冻结**这个前提第一次成立时才可重开——那时两个数才可能落在
  同一个视图里。在此之前，任何「加个百分比吧」的提议都撞本节。
- §6 的「终结即丢投影」在 M4 引入延迟批次重推（ADR-0018）时重开：`INCOMPLETE` 是跨进程的
  可恢复状态，「run 结束了投影就没用了」届时不成立。
