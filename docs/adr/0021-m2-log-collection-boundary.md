# ADR-0021: M2 的采集边界——业务值不出主机，UI 是唯一出口且靠 `listen` 兜底，JSON Lines 留任主载体

**状态**: 已接受
**日期**: 2026-08-15
**来源**: [#50](https://github.com/liumingjian/db-qbs/issues/50)（地图 [#47](https://github.com/liumingjian/db-qbs/issues/47)）
**关联**: [ADR-0017](0017-run-log-format-and-contract.md)（**§1 载体复审、§2 新增第六个公共字段、§4 兜底条款、§6.1 由本 ADR 订正**）、
[ADR-0019](0019-m2-source-process-topology.md)（长驻编排 + 短命子进程；**§1「子进程一行不改」由本 ADR 破一次例，见 §3**）、
[ADR-0020](0020-m2-run-history-store.md)（运行历史落 source 侧 SQLite——业务值离开 stdout 的实际路径）、
[ADR-0016](0016-task-definition-form.md)（§8 凭据明文 0600，本 ADR 的缺口记账与它同档）、
[ADR-0013](0013-verification-gate-row-counting.md)（§7 校验失败即 `DROP`，日志是唯一线索——§2 否掉「不打值」的依据）

## 背景

ADR-0017 §时效有两条点名要在 M2 重开：

> **「第 1 节的载体在 source 变长驻（M2 引入 Web UI）时复审」**
>
> **「第 4 节的『值可打』绑在『日志文件权限 0600 且不外采』上。一旦日志要采集到目标端之外
> 或接入集中式日志系统，这条必须先重开——那时它就不再是文件权限能兜住的事。」**

本 ADR 是那两次重开。但它面对的不是一件将来可能发生的事：

> **日志已经被采走了。** [ADR-0020](0020-m2-run-history-store.md) §7 让父进程把
> `run_finished.column` / `value` 原样抄进 source 侧 SQLite 的历史行，
> [ADR-0019](0019-m2-source-process-topology.md) §9 让这些行经 `/api/*` 送进浏览器。
> **采集者是我们自己的父进程，出口是 UI。** 0600 兜底的适用面在 M2 起图那一刻就已经破了，
> 本 ADR 是补账，不是预防。

M1 那条「值只活在 stdout、进程退出即蒸发」的自然边界，同时被三件事拆掉：source 变长驻、
历史落盘、UI 可远程读。三件都是 M2 主方向的直接产物，一件都退不掉。

## 决策

### 1. 采集边界画在**主机**上，不画在文件权限上

> **业务数据值可以存在于 `source` 服务主机上的三个载体里：子进程 stdout、部署者自行重定向出的
> 文件、以及运行历史 SQLite。把这三者中任何一个的内容送出该主机，都是外采——M2 不提供、
> 不支持、不为其留接口。**

线的定义从「文件权限」换成**进程边界 + 主机边界**。三条候选线里：

- **「进程组内」不成立**——它要求业务值不落任何盘，而 ADR-0020 的历史行本身就是落盘，
  这条线在本图上一票就已经越过去了。
- **「信任域内」（同网段收集器 / 集中式日志）被否**：它唯一的驱动力是运维便利，
  而 M2 没有任何一票依赖它。集中式日志一旦接上，0600 与主机边界同时失效，
  值的去向变成一个我们既不知道也管不着的东西。**它属地图的 Out of scope，不是本 ADR 的缺口。**

**这条线不禁止部署者自己 `> run.jsonl`**——ADR-0017 §6.1 那句「是否重定向由部署者决定」不变，
落出来的文件仍须 `umask 077` / 0600。变的是这句话后面半句的措辞归属：
「不得采集到目标端之外」从一条**建议**变成一条**画在主机上的规格边界**。

### 2. 「值可打」保留原样，兜底从**文件权限**换成**监听地址与部署形态**

ADR-0017 §4 的三选一，选**保留**：值照打进 stdout、照抄进历史行、照显示在 UI 上。

**换掉的兜底写死成这一条：**

> **`source` 服务的可达范围就是业务值的暴露范围。** M2 不做鉴权（V1 非目标），
> 因此**任何能连上 `source` 服务端口的人，都能在运行历史里读到源库的真实业务值**。
> 收敛这个范围的唯一手段是 §4 的 `listen`。

**否掉另外两个选项的致命处：**

- **「值在采集边界上被剥离」**（父进程写历史行时只写 `column`、不写 `value`）：当场废掉
  [#35](https://github.com/liumingjian/db-qbs/issues/35) 为 `ERROR 1292` 定的
  「措辞要点名**是哪一列、哪个值**」——那是 M1 花一整票定下的排障底线，
  同形状还管着 `ERROR 1264` / `1366`。留下的是一堆知道「哪一列」却说不出「哪个值」的空壳行。
- **「值根本不再打」**：ADR-0013 §7 校验失败即 `DROP` 暂存表、不留现场，
  日志是唯一可能留线索的地方。抹掉值等于 M2 用一个更好看的 UI 换走了 M1 的排障能力，
  与「让 M1 那条链路第一次有人能用地跑起来」这个主方向反向。

**这条决策改变 [#54](https://github.com/liumingjian/db-qbs/issues/54) 的输入**：鉴权重新定价的问题
从「凭据明文值不值得管」变成「**不做鉴权 + 默认只听回环**够不够」。本 ADR 不替它作答。

### 3. JSON Lines 留任主载体；父子两股日志混同一条流，靠新增的第六个公共字段分辨

ADR-0017 §1 复审的结论是**不变**：载体仍是 stdout 上的 JSON Lines，
父进程（长驻编排）与子进程（M1 那个一次性进程）**用同一套契约、写同一条流**。

判据仍是 ADR-0017 §1 那句「结构在字段上，不在排版上」——而它在 M2 只增强不减弱：
消费者比 M1 更多（父进程 + 排障 Agent + 人），父进程另起一套排版等于在同一个服务里养两种取证面。
「有了 UI 就不需要 stdout 了」不成立：UI 显示的是**历史投影**，取证面仍然是日志本身。

**新增公共字段 `component`**，公共字段由五个变六个：

| 字段 | 类型 | 值域 |
|---|---|---|
| `component` | string | `source-orchestrator`（长驻父进程）/ `source-run`（短命子进程）/ `sink` |

- **否掉「靠 `event` 名前缀隐式区分」**：把可分辨性藏进命名约定，下游要写前缀匹配——
  正是 §1 拒绝过的病。
- **否掉「复用 `task` 字段，父进程行恒为 `null`」**：`task` 的 `null` 在 M1 已有确定语义
  （sink 对任务定义一无所知，ADR-0016 §5），再压一层就是 ADR-0020 §8 刚判过的「一名两义」。

**兼容规则**：这是 ADR-0017 §5 契约收紧后的**第一次新增**（新增仍自由，是收紧后唯一留着的方向）。
**M1 已落盘的旧日志行没有这个字段——消费者读到缺席时一律按 `source-run` 解释**，
不得报错、不得当作未知产生端。

**破 ADR-0019 §1 一次例，正面认账**：`source-run` 是「M1 那个一行不改的子进程」，
它要打 `component` 就得改一行。本 ADR 认为可接受，理由是改的是**日志字段而非搬运逻辑**
（收窄 1 管的是搬运语义，此处没碰），且 ADR-0017 §5 明确允许新增。
但「子进程零改动」这句从此不再逐字成立，**它的准确表述是「搬运链路零改动」**。

### 4. `listen` 必填、允许非回环、非回环时启动打一条 `warn`

长驻的 `source` 第一次需要监听配置。**键名与形状复刻 sink**（`crates/sink/src/lib.rs`）：

```toml
listen = "127.0.0.1:8088"
```

- **必填，不给默认值**，空串即启动失败——照 sink 的口径。
  不设「安全默认」是有意的：默认值是会被无意识覆盖的东西，而必填让部署者**显式写出**
  这个服务听在哪，那正是 §2 的兜底所在。
- **允许配成非回环**。不允许等于把产品做成单机玩具，而 UI 的全部意义是别人能用。
- **配成非回环时，启动横幅打一条 `level: warn` 的日志行**，人话必须点明：
  本服务无鉴权、运行历史含源库业务数据值、当前监听地址、该网络内任何人可读。

**这条 `warn` 不是拦截**——拦截就是变相做了半个鉴权，擦收窄 2 的边。它的作用是
**让缺口在被拆掉的那一刻留痕**：§2 换来的兜底是部署形态，若拆掉时无声无息，
它比 0600 还弱（0600 至少要人主动 `chmod`）。

### 5. 采集侧没有独立职责，它是运行历史的实现细节

[#49](https://github.com/liumingjian/db-qbs/issues/49) 选了「留存用存储」之后，
「M2 的采集侧」这个在 ADR-0017 背景里被写成日志主消费者之一的东西，**收缩成 ADR-0020 §1 那一段
父进程读子进程 stdout**——同机、同进程组、不出网。

> **M2 不存在一个待建的「采集侧」组件。** 除父子那一段之外的一切外采都不做。

本 ADR 真正定的，是这段采集**之外**的边界，以及为此付的三笔账（§2 的暴露面、§6 的无界增长、
§7 的值寿命）。

### 6. stdout 无界增长：程序不管，作为**第三条明知缺口**记账

ADR-0017 §6.1「程序自身不创建日志文件、不轮转」在长驻形态下有个 M1 没有的后果：
**服务跑上几个月，stdout 无限增长且无轮转**。

**决策：原样不动**，程序仍不建文件、不轮转。

- **否掉「程序自建文件并自轮转」**：把运维职责搬进产品，不在「让 M1 那条链路第一次有人能用地
  跑起来」这条线上。
- **否掉「把 systemd + journald 写进部署规格」**：看着稳妥，实则等于默认接受 journald
  这条采集路径——journald 默认可被 `systemd-journal` / `adm` 组读、还能 forward 到 syslog，
  §1 判它越界。

**但这条缺口必须显式记账，不沉默继承**：M1 的「不轮转」代价是有界的（进程跑完即退），
长驻下无界。它进 `CONTEXT.md` 的缺口清单，与 ADR-0016 §8 凭据明文、ADR-0017 §4 日志含值
**同档同形式**——形式一致才不会被漏读。这是第三条。

### 7. 业务值在磁盘上的寿命从「进程退出即消失」变成 90 天，接受

M1 的值只活在 stdout，部署者不重定向就随进程蒸发。M2 的 `column` / `value` 被抄进历史行，
按 ADR-0020 §9 留 **90 天**。**决策：接受，值与历史行同寿。**

- **否掉「给 `value` 单列一个更短的擦除窗口」**：收益是假的。需要值的时刻，恰恰是有人隔了很久
  回来问「上个月那次为什么失败」——短窗口专门擦掉的就是这种场景里唯一有用的那个字段。
- **否掉「值不进 SQLite，UI 要看就去查 stdout」**：违背 ADR-0020 §1「历史行的作者是父进程，
  不是日志」，让 UI 回头查一个**可能压根没被重定向**的 stdout，是被否掉的纯 B 路线借局部字段还魂。

**代价明写并进术语表**：

> **运行历史 SQLite 文件在 90 天内持有源库真实业务值样本，其敏感级别与 ADR-0016 §8 的凭据文件
> 同档，权限须为 0600。**

这是 §1 那条主机边界上**第二个必须点名的载体**（第一个是部署者重定向出的 stdout 文件）。

## 对 ADR-0017 的订正

| 节 | 订正 |
|---|---|
| §1（载体） | 时效兑现：**复审结论是不变**，JSON Lines 留任主载体；新增「父子同流」与 `component` 分辨规则 |
| §2（公共字段） | 五个 → **六个**，新增 `component`；旧行缺席按 `source-run` 解释 |
| §4（值可打） | 兜底条款由「文件权限 0600 且不外采」改为「主机边界 + `listen` 可达范围」；0600 仍是主机内三个载体的权限口径，但不再是**唯一**兜底 |
| §6.1（只写 stdout） | 「不得采集到目标端之外」升格为规格边界（§1）；补记无界增长缺口（§6） |
| §6.2（闭集） | 新增启动横幅的 `warn` 行属父进程事件，随 M2 实现定稿时补进闭集；本 ADR 只定它必须存在与必须说什么 |

## 后果

- **M2 的敏感数据暴露面第一次被完整写出来**：不是「日志文件含值」一句，而是三个载体
  （stdout、重定向文件、历史 SQLite）+ 一条远程读取面（UI），兜底从文件权限换成主机边界与 `listen`。
- **`CONTEXT.md` 的明知缺口从两条变四条**：凭据明文、日志含值、**stdout 无界增长**、
  **历史 SQLite 持值 90 天**。前两条在引入鉴权时一并重开，后两条各有各的时效。
- **ADR-0019 §1「子进程一行不改」降级为「搬运链路零改动」**——`component` 是第一次也是唯一一次
  对子进程的日志侧改动。
- **[#54](https://github.com/liumingjian/db-qbs/issues/54) 的问题形状变了**：从「凭据明文值不值得管」
  变成「不做鉴权 + 默认只听回环够不够」，且它现在有两个新输入（业务值经 UI 可读、SQLite 持值 90 天）。
- **「采集侧」这个词从待建组件降为实现细节**，`CONTEXT.md` 里那句「主消费者是排障 Agent
  与 M2 的采集侧」随之订正。

## 时效

- **§2 的兜底在引入鉴权时整体重开**——那时「可达范围 = 暴露范围」不再成立，
  与 ADR-0016 §8 凭据明文一并处理。
- **§6 的无界增长**：一旦有部署反馈说 stdout 真的撑爆磁盘，「程序自建文件并自轮转」重开。
- **§7 的 90 天**：若出现监管或客户口径要求业务值样本不得留存，`value` 的独立擦除窗口重开——
  届时要连带重判 #35 的措辞要求。
- **§1 的主机边界**：若将来真有一条「必须接集中式日志」的硬需求，它不是本图的续做，
  是重画终点、另起一图。
