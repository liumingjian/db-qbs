还没有任务
一个任务是四个字段：一段 source_sql、source_date_col、 target_table、target_date_col（ADR-0016 §2）。 业务日期不在任务里——它是每次发起时才填的运行参数。 不会写 SQL 就用构建器选表选列生成一段；已经有现成 SQL 就直接粘。
① 选表与列 元数据来自 Oracle 数据字典，只亮不判
数据库链接FA 表htbr45.t_r_fr_aststat
数据库链接可选：填了 FA，本次会话所有字典查询走 ALL_TAB_COLUMNS@FA， 生成的 SQL 表名也带 @FA。不给下拉列表——ALL_DB_LINKS 只列当前用户可见的 link， 列不全反而误导（ADR-0023 §3）。链接后面若是同义词，构建器列不出它的列，那时请直接粘 SQL。
列名字典类型精度判定
N_VA_PRICENUMBER(18,4)白名单内
C_NAMEVARCHAR2(50)白名单内
D_BIZDATE—白名单内
C_MEMOCLOB—M1 白名单外，预检大概率会拒
TS_UPDTIMESTAMP(6)—M1 白名单外，预检大概率会拒
后两行点得动、勾得上，构建器不拦。类型判定的权威是 sink 侧的映射预检（ADR-0023 §4）： 字典与运行期的游标 describe 是两份元数据，视图与 dblink 之下可以不一致—— 拿非权威的那份做门禁，会造出「构建器拒了、其实能跑」。
勾成真子集是允许的（ADR-0009 增补 §1）：对齐面是「SQL 结果集 ↔ 目标表」，源表不参与。 但目标表里有列没被选中会被预检硬拒（§4）——那是跑不起来，不是搬错。
② 指定日期列
这里没有业务过滤条件输入框，不是漏了。日期谓词由系统按半开区间生成 （>= TO_DATE(:biz_date) 且 < +1，ADR-0008 §3）； AND status = 'X' 这类谓词被 ADR-0008 §2 硬拒—— 切换时的清除条件只按日期删，加了业务谓词就会连同日期相同、条件不同的存量数据一起删掉， 而行数校验结构性抓不到这件事。
③ 目标端
目标表T_POSITION
目标日期列D_BIZ
两个字段都人手填，目标日期列预填成源端日期列名、可改（ADR-0023 §7）。 这里没有目标表下拉、没有目标列列表，是不画，不是没画完—— source 不查目标端元数据（ADR-0027 §3）：那条接口能买到的只有一个下拉框， 买不到任何一处拦截，却要给协议闭集加一类不属于任何 run 的请求。
④ SQL 这一段文本才是任务定义存的东西

目标表建表 SQL 取列之后在此给出
点上面的「取列」拿建表 SQL。取列会连一次 Oracle 跑 prepare + describe， 只读、不碰目标端、不产生运行记录。

这一屏就是「建任务」的全部。 向导 ①②③ 的选择状态不进任务定义—— 落盘的永远只有 ④ 的四个字段（ADR-0016 §2 格式一字未变）。
